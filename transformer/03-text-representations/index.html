03 文本的数学表示：Token、Embedding 与 Tensor

发表于2026-09-29|更新于2026-09-30|「CV」看得见的计算机视觉从神经网络到 Transformer
|浏览量:

前两章讨论的网络与概率模型都以数值张量作为输入，然而文本本身是字符串。因此，在字符串进入 Transformer 的第一层之前，需要先经过一条固定的处理路径：

在这条路径上，每个对象的作用各不相同：token 是切分的基本单位，编号是它在词表中的身份，Embedding 是可学习的参数表，而批量张量则是网络真正参与计算的对象。在实践中，混淆这些对象往往是许多实现错误（如填充位置参与计算、掩码方向写反）的根源。

1. 分词：确定基本单位

1.1 分词粒度

处理文本的第一步，是由分词器 (Tokenizer) 把字符串切分为一串词元 (token)。根据切分的粒度，常见的方案可以分为以下三种：

  • 词级 (word-level)：一个词对应一个 token。这种方式的序列较短，单位的含义也较完整，但词表会非常大，并且无法处理训练时未见过的词（即未登录词，out-of-vocabulary, OOV），只能将它们统一映射为未知标记。
  • 字符级 (character-level)：一个字符对应一个 token。这种方式的词表较小；若字符表覆盖输入字符，就可以避免词级 OOV 问题，但遇到字符表之外的字符仍需额外处理，但序列会显著变长，模型需要从字符出发重新组合出词义。
  • 子词级 (subword-level)：介于上述两者之间，高频词保留为一个整体，而低频词则被拆分为若干高频片段。例如，英文单词 unhappiness 可以被拆分为 un / happi / ness。

由于子词分词在词表大小、序列长度和 OOV 处理之间取得了较好的平衡，当前的主流模型几乎都采用了这一方案。

下图以一个见过的词和一个没见过的词为例，对比了三种粒度的切分结果。可以看到，词级方案遇到新词时只能输出未知标记，字符级方案的序列明显变长，而子词级方案则能用已有的片段组合出新词。

1.2 BPE 的合并过程

在各种子词算法中，字节对编码 (Byte Pair Encoding, BPE) 是最常用的一种，它由 Sennrich 等人于 2016 年引入神经机器翻译领域。其基本思想是：从单个字符出发，反复把语料中出现频率最高的相邻符号对合并为一个新符号。

此外，子词算法还有几种常见的变体。WordPiece（BERT 所使用的方案）依据合并后语料似然的提升程度、而非单纯的频次来选择合并对象；SentencePiece 把空格也当作普通字符处理，因此适用于中文、日文等不以空格分词的语言；而从 GPT-2 开始采用的字节级 BPE (byte-level BPE) 则以 UTF-8 字节作为初始单位，任何字符串都能够被编码，因而不再需要未知标记。

1.3 分词器训练与模型训练

需要注意的是，分词器的训练与语言模型参数的训练是两个相互独立的过程。前者根据语料统计确定切分规则和词表，完成之后便保持固定；后者则学习每个 token 的向量表示以及网络的其余参数。因此，一个训练好的模型必须与它配套的分词器一起使用，如果换用其他分词器，编号与参数表之间就会发生错位。

另外，分词方式还会影响模型的计算成本。同一句话在不同分词器下得到的 token 数量可能相差数倍，而 Transformer 的注意力开销会随序列长度的平方增长（第 11 章）。

2.1 一个示例词表

2.2 编号与独热表示

在得到编号之后，一个自然的问题是：能否直接把编号作为数值输入网络？答案是否定的。编号只是一个标识：例如，“我”的编号为 4，“你”的编号为 6，二者的差值 2 并没有任何语义；并且，如果把词表整体重新排列，只要同步调整模型中所有按词表索引的参数，模型的行为就完全不会改变。因此，编号不能直接作为数值特征送入网络。

一种直接的替代方案是独热表示 (one-hot representation)，它用一个长度为 $V$ 的向量标记类别身份：当前编号的位置取 1，其余位置取 0。例如，“我”对应的独热向量为：

然而，任意两个不同 token 的独热向量都相互正交，它们之间的欧氏距离也都相同。换言之，这种表示虽然能够区分身份，却不包含任何相似性信息：“猫”和“狗”之间的距离，与“猫”和“量子”之间的距离完全相同。此外，当词表规模达到数万时，独热向量也会变得极其稀疏。因此，在实际实现中，输入通常以 torch.long 类型的整数编号存储，再由 Embedding 层直接按索引查表，而不会显式地构造独热向量。

3.3 Embedding 的学习

Embedding 参数与网络的其余参数一起，通过反向传播进行更新。如果同一个编号在一个批次中出现多次，那么各次使用都会指向同一行参数，相应的梯度也会累加到这一行上。训练完成后，在相似上下文中出现的 token 往往会获得相近的向量，这对应于语言学中的分布假设 (distributional hypothesis)：一个词的含义由它经常出现的上下文所决定。word2vec（Mikolov 等，2013）就是专门利用这一假设来预训练词向量的方法；与之不同，Transformer 中的 Embedding 通常与整个模型一起进行端到端训练。

此外，不少模型还让输入 Embedding 与输出层的词表投影共享同一个参数矩阵，这一做法被称为权重绑定 (weight tying)，原始 Transformer 同样采用了这一设计（第 10 章）。

4. 上下文化表示与位置信息

4.1 静态向量的局限

虽然 Embedding 解决了相似性的表示问题，但它仍然存在一个局限：查表过程只依赖于编号。也就是说，同一个 token 在任何句子中查出的都是同一个向量，因此无法区分多义词，例如“苹果发布了新手机”与“把苹果削皮”中的“苹果”，或者 bank 在金融语境与河流语境中的不同含义。

为了解决这一问题，需要借助具备跨位置交互能力的网络，把上下文信息带入每个位置的表示中。设第 $\ell$ 层中位置 $i$ 的隐藏向量为 $h_i^{(\ell)}$，它的依赖关系可以写为：

其中，$e_j$ 是位置 $j$ 的初始向量，$\theta$ 是网络参数，而“可见范围”则规定了该位置允许读取哪些输入（例如全句，或仅限已有前缀）。这样一来，两处相同的 token 虽然初始向量相同，但由于周围的输入不同，就可以得到不同的 $h_i^{(\ell)}$，这种表示被称为上下文化表示 (contextualized representation)。需要注意的是，它是一次前向计算中产生的激活，模型并没有为每个句子新建一张 Embedding 表。ELMo、BERT 等模型的主要贡献之一，正是用上下文化表示取代了静态词向量。

4.2 位置信息

除了上下文之外，另一类差异来自顺序。例如，“我喜欢你”与“你喜欢我”的 token 集合完全相同，差别只在于位置。第 08 章将会证明，不含位置信息的自注意力对输入的排列是等变的：交换两个输入的位置，只会同样地交换对应的输出，因此模型无法据此判断谁在前、谁在后。所以，Transformer 需要在输入中显式地加入位置编码 (positional encoding)。其中，Token Embedding 提供身份信息，位置编码提供次序信息，二者相加之后再进入网络。

图中沿用第 3.2 节的嵌入参数，只保留“我／喜欢／你”三个普通 token，并将它们的位置编号设为 0、1、2。查表结果记为 $X$；原始 Transformer 将其乘以 $\sqrt D$ 后，与正余弦位置编码 $PE$ 逐元素相加，得到输入表示 $H=\sqrt D\,X+PE$。本例 $D=4$，缩放系数为 2。

5.2 transpose 与 reshape

需要注意的是，不同接口可能采用不同的轴顺序。例如，nn.Transformer 与 nn.MultiheadAttention 默认使用 [L,B,D]，只有设置 batch_first=True 才会改为 [B,L,D]。在这种情况下，可以使用 transpose(0, 1) 交换样本轴与位置轴：每个元素仍然对应原来的样本和位置，只是访问顺序发生了变化。

与之不同，reshape 按照内存中的元素顺序重新划分形状，一般不能代替轴交换。例如，把 [2,5,4] 的张量 reshape 为 [5,2,4]，虽然形状与转置的结果相同，但元素与样本、位置之间的对应关系已经被打乱，而程序并不会报错。由此可见，张量的意义由形状、轴的语义以及元素的对应关系共同确定，仅仅检查形状并不足以保证正确性。

同样的问题也出现在注意力机制中：即使填充位置的 Value 为零，它仍然会在 softmax 中分走一部分权重，从而减少有效位置所获得的总权重。因此，填充位置必须在 softmax 之前就被屏蔽（第 07 章）。更何况，在加入位置编码或偏置之后，填充位置的表示通常也不再为零。

6.2 三处需要处理填充

具体而言，一个批次中的填充需要在以下三个地方分别处理，并且它们之间不能相互替代：

  1. 注意力的 Key：使用 padding mask，阻止任何位置读取填充位置。
  2. Query 的输出：屏蔽 Key 并不能让填充位置自身的输出为零，因此在对输出进行池化或聚合时，需要再次按掩码排除这些位置。
  3. 损失函数：填充位置的标签不应计入损失。对于交叉熵，可以使用 ignore_index 忽略指定的标签编号。
