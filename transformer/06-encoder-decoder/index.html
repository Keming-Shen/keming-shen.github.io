CH-06 编码器与解码器

发表于2026-09-29|更新于2026-10-09|「CV」看得见的计算机视觉从神经网络到 Transformer
|浏览量:

在许多任务中，输入与输出都是序列，但两者的长度、顺序乃至模态都可能不同。例如，机器翻译把一种语言的句子转换为另一种语言，语音识别把声学帧序列转换为文字，而图像描述 (image captioning) 则把一张图片转换为一句话。对于这类任务，编码器—解码器 (Encoder–Decoder) 是一种通用的处理结构：编码器负责把输入转换为中间表示，解码器则根据中间表示生成输出。

这一划分方式与具体的网络类型无关，它既可以用 RNN 实现，也可以用 CNN 或注意力机制实现。真正决定模型能力的，是二者之间的接口：中间表示究竟是一个向量还是一组向量，以及解码器在每一步如何读取它。

1. 序列到序列映射

1.1 问题形式

首先形式化地描述这一问题。记源序列为 $x=(x_1,\ldots,x_n)$，目标序列为 $y=(y_1,\ldots,y_m)$，模型需要计算的是条件概率 $p_\theta(y\mid x)$。在一般情况下，源序列长度 $n$ 与目标序列长度 $m$ 并不相同，并且位置之间也不存在固定的对应关系。

以英译中为例：I / like / you / very / much 包含 5 个 token，而“我 / 很 / 喜欢 / 你”只包含 4 个；并且，英文句末的 very much 对应的是中文动词前的“很”。由此可见，翻译不仅需要建立内容上的对应关系，还需要处理长度的变化与语序的调整，因此不能简单地把相同位置上的词逐个替换。

同样的分工也出现在其他领域中。例如，在语音识别中，编码器处理的是声学特征；在图像描述中，编码器是一个 CNN 或视觉 Transformer；而这两种示例结构的解码器均是 autoregressive 文本生成器。虽然输入层、损失函数和生成规则会随任务而变化，但“编码输入—条件生成”这一计算关系始终保持不变。

2. RNN Seq2Seq 与固定长度上下文

2.1 结构

2.2 单一上下文向量的限制

具体来说，无论源句有多长，解码器所能获得的都只是一个固定维度的向量 $c$。因此，源句越长，需要压缩进同样维度的信息就越多。Cho 等人在同年的分析中观察到，这类模型的翻译质量会随着句子长度的增加而明显下降。这种现象通常称为 fixed-length context bottleneck，指完整源序列只能通过一个固定维度的状态影响解码器。状态维度、训练数据与优化方法都会影响压缩的信息量，因此不能仅凭源句长度推断具体误差。

4. 保留全部源位置

若解码器只能访问句末状态，较早源位置的细节必须经过多次状态传递。因此，增加可访问的源端状态，可以缩短解码器获取这些信息的路径。编码器在得到最终状态 $h_n$ 的过程中，已经计算出了每个源位置的状态。如果把它们全部保留下来，就得到了一个随源序列长度增长的源表示：

其中，分号表示按位置堆叠。这组向量通常被称为 memory。源句越长，保留的向量就越多。解码器不再必须从一个句末向量恢复全部内容，而可以在不同生成步骤读取不同的源位置。编码器仍然需要在每个位置形成有用的有限维表示。

不过，这里需要区分两个不同的属性：一是保留了多少个位置，二是每个位置包含了多大范围的上下文。例如，单向 RNN 的 $h_j$ 只包含位置 $j$ 及其之前的输入；双向 RNN 把正向与反向的状态拼接在一起，因此每个位置都能看到整个句子；而 Transformer 编码器则通过 self-attention（自注意力），让每个位置直接读取其余所有位置。由此可见，memory 是经过上下文计算之后的表示，而不是原始词向量的简单集合。

下图对比了三种编码器：它们都保留了三个状态，但每个状态所依赖的输入范围各不相同。

另外，在离线翻译中，模型在生成开始之前就已经获得了完整的源句，因此目标的每一步都可以读取任意的源位置，而自回归的限制只作用于目标序列。与之不同，同声传译、流式语音识别等任务的输入是陆续到达的，因此源端的可见范围还需要另行约束。

5. 注意力：按需读取 memory

5.1 Bahdanau 注意力

有了 memory 之后，还需要一种机制来决定解码器在每一步应该读取什么内容。对此，Bahdanau 等人在 2014 年提出了如下方法：首先，用当前的解码状态 $s$ 与每个源表示 $h_j$ 计算匹配分数；然后，将这些分数归一化为权重；最后，用权重对源表示进行加权求和：

在这一机制中，上下文向量 $c$ 会在每一步重新计算。当解码状态发生变化时，分数、权重与读取结果也会随之变化，因此解码器在生成不同的目标词时，可以关注源句中的不同部分。如果把这些权重可视化，往往可以看到近似于词对齐 (word alignment) 的模式。

为了更具体地理解这一机制，下图展开了解码某一步时的完整计算过程：解码状态先与每个源状态打分，分数经 softmax 转换为权重，最后按权重对源状态求和得到上下文向量。

5.3 cross-attention 与 self-attention

像上面这样，读取需求来自一个序列（目标侧状态）、而被读取的内容来自另一个序列（源侧 memory）的注意力，被称为cross-attention（交叉注意力）。其中，Query 与 Key/Value 来自不同序列，但不要求两个序列属于不同模态。与之相对，self-attention 则是在同一个序列内部进行位置之间的信息聚合。

具体而言，如果目标侧有 $m$ 个查询位置、源侧有 $n$ 个位置，那么权重矩阵的形状为 $m\times n$，其中每一行表示一个目标位置对全部源位置的权重分配。在这种情况下，源端的补齐位置需要被屏蔽，而其余的源位置则全部可见，包括位于句子后半部分的内容。因此，cross-attention 中的掩码与目标 self-attention 中的 causal mask（因果掩码），其含义是完全不同的。

在反向传播时，梯度从解码器的输出出发，经过状态传递或注意力聚合，一直传递到编码器的参数。例如，前面代码中的一次 loss.backward()，就同时为两部分的 Embedding 计算了梯度。因此，编码器受到的是当前序列任务的监督，其源表示需要保留有助于目标预测的信息。该目标本身不保证表示对其他任务同样有效。

而在推理方面，同一个源句只需要编码一次，得到的 memory 可以在所有生成步骤中复用。为此，可以把模型拆分为 encode(source) 与 decode(prefix, memory) 两个接口，从而直接表达这一数据流；相比之下，如果每一步都调用完整的 model(source, prefix)，虽然结果相同，却会重复执行源侧的计算。

7. 编码器—解码器与自编码器

最后，需要区分两个名称相近的概念。自编码器 (Autoencoder) 是另一类模型：它先把输入 $x$ 编码为中间表示，再将其重建为 $\hat x$，并以重建误差作为训练目标，常用于降维、去噪和表示学习。相比之下，翻译模型虽然同样包含编码器和解码器，但它的目标是另一个序列，因此属于序列转换任务。简而言之，“编码器—解码器”描述的是结构上的分工，而“自编码器”描述的是训练任务。

此外，编码过程也并不以“压缩”为必要条件。例如，Transformer 编码器的每一层都保持序列长度和模型维度不变，它所追求的是适合下游任务的表示，而不是更小或可逆的表示。

下图把这几种结构放在一起对比：

这一套组件还可以拆开来单独使用：如果只保留编码器，并在其上接入分类头或逐位置预测头，就可以用于文本分类与序列标注（如 BERT）；如果只保留带 causal mask 的解码器，则可以用于语言建模与文本续写（如 GPT）。而原始 Transformer 同时保留了两者，并通过 cross-attention 将它们连接起来：编码器处理完整的源序列，解码器处理目标前缀，而 cross-attention 则在每一层把源信息引入目标位置。

CH-05 自回归模型与序列建模
生成一段文本时，模型既要决定每个位置的内容，也要确定输出在何处结束。直接为所有可能句子建立概率表，会随长度和词表规模产生指数级的组合数量。Autoregressive modeling 将这一问题分解为根据已有前缀预测下一个 token 的条件分布。 “Autoregressive”一词来自时间序列分析。在统计学中，AR($p$) 模型用过去 $p$ 个时刻的观测值来线性预测当前值，例如，用最近几天的气温来预测今天的气温。由于变量是对“自身的过去”进行回归，因此得名。 在语言建模中，模型把同样的思想推广到离散的 token 序列上，并且去掉了“线性”与“固定窗口”两个限制：它用神经网络，根据可访问的已有前缀预测下一个 token 的概率分布。前缀的可用长度受模型配置与计算资源限制。GPT 系列、机器翻译中的解码器以及代码补全模型，均可采用这一条件预测方式。 下图对比了两者：左侧的 AR 模型只用固定窗口内的若干个观测值进行线性组合；右侧的语言模型则用神经网络读取任意长度的前缀，并输出整个词表上的概率分布。 图1....
