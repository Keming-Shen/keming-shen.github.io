06 编码器与解码器

发表于2026-09-29|更新于2026-10-01|「CV」看得见的计算机视觉从神经网络到 Transformer
|浏览量:

在许多任务中，输入与输出都是序列，但两者的长度、顺序乃至模态都可能不同。例如，机器翻译把一种语言的句子转换为另一种语言，语音识别把声学帧序列转换为文字，而图像描述 (image captioning) 则把一张图片转换为一句话。对于这类任务，编码器—解码器 (Encoder–Decoder) 是一种通用的处理结构：编码器负责把输入转换为中间表示，解码器则根据中间表示生成输出。

值得一提的是，这一划分方式与具体的网络类型无关，它既可以用 RNN 实现，也可以用 CNN 或注意力机制实现。真正决定模型能力的，是二者之间的接口：中间表示究竟是一个向量还是一组向量，以及解码器在每一步如何读取它。

1. 序列到序列映射

1.1 问题形式

首先形式化地描述这一问题。记源序列为 $x=(x_1,\ldots,x_n)$，目标序列为 $y=(y_1,\ldots,y_m)$，模型需要计算的是条件概率 $p_\theta(y\mid x)$。在一般情况下，源序列长度 $n$ 与目标序列长度 $m$ 并不相同，并且位置之间也不存在固定的对应关系。

以英译中为例：I / like / you / very / much 包含 5 个 token，而“我 / 很 / 喜欢 / 你”只包含 4 个；并且，英文句末的 very much 对应的是中文动词前的“很”。由此可见，翻译不仅需要建立内容上的对应关系，还需要处理长度的变化与语序的调整，因此不能简单地把相同位置上的词逐个替换。

事实上，同样的分工也出现在其他领域中。例如，在语音识别中，编码器处理的是声学特征；在图像描述中，编码器是一个 CNN 或视觉 Transformer；而两者的解码器都是文本的自回归生成器。虽然输入层、损失函数和生成规则会随任务而变化，但“编码输入—条件生成”这一计算关系始终保持不变。

2. RNN Seq2Seq 与固定长度瓶颈

2.1 结构

最早的 Seq2Seq 模型是基于 RNN 实现的。2014 年，Sutskever 等人与 Cho 等人分别提出了这一结构。具体而言，编码器按顺序读入源序列，并不断更新隐藏状态：

2.2 信息瓶颈

具体来说，无论源句有多长，解码器所能获得的都只是一个固定维度的向量 $c$。因此，源句越长，需要压缩进同样维度的信息就越多。Cho 等人在同年的分析中观察到，这类模型的翻译质量会随着句子长度的增加而明显下降。这就是所谓的固定长度瓶颈 (fixed-length bottleneck)。当然，它的实际影响还取决于状态维度、训练数据和优化效果，但从本质上说，这是一种结构性的限制。

4. 保留全部源位置

既然固定长度的上下文向量存在瓶颈，那么一个自然的改进思路是保留更多的信息。事实上，编码器在得到最终状态 $h_n$ 的过程中，已经计算出了每个源位置的状态。如果把它们全部保留下来，就得到了一个随源序列长度增长的源表示：

其中，分号表示按位置堆叠。这组向量通常被称为 memory。这样一来，固定长度瓶颈就被消除了：源句越长，保留的向量就越多，解码器也可以在不同的生成步骤中读取不同的位置。

不过，这里需要区分两个不同的属性：一是保留了多少个位置，二是每个位置包含了多大范围的上下文。例如，单向 RNN 的 $h_j$ 只包含位置 $j$ 及其之前的输入；双向 RNN 把正向与反向的状态拼接在一起，因此每个位置都能看到整个句子；而 Transformer 编码器则通过自注意力，让每个位置直接读取其余所有位置。由此可见，memory 是经过上下文计算之后的表示，而不是原始词向量的简单集合。

另外，在离线翻译中，模型在生成开始之前就已经获得了完整的源句，因此目标的每一步都可以读取任意的源位置，而自回归的限制只作用于目标序列。与之不同，同声传译、流式语音识别等任务的输入是陆续到达的，因此源端的可见范围还需要另行约束。

5. 注意力：按需读取 memory

5.1 Bahdanau 注意力

有了 memory 之后，还需要一种机制来决定解码器在每一步应该读取什么内容。对此，Bahdanau 等人在 2014 年提出了如下方法：首先，用当前的解码状态 $s$ 与每个源表示 $h_j$ 计算匹配分数；然后，将这些分数归一化为权重；最后，用权重对源表示进行加权求和：

Bahdanau 注意力使用加性评分函数 $\operatorname{score}(s,h_j)=v^\top\tanh(sW+h_jU)$，其中 $W,U,v$ 为可学习参数，因此这种方法也被称为加性注意力 (additive attention)。随后，Luong 等人（2015）比较了几种更简单的乘性形式，例如 $\operatorname{score}(s,h_j)=sWh_j^\top$。而 Transformer 所采用的缩放点积注意力，正是乘性形式的一种（第 07 章）。

在这一机制中，上下文向量 $c$ 会在每一步重新计算。当解码状态发生变化时，分数、权重与读取结果也会随之变化，因此解码器在生成不同的目标词时，可以关注源句中的不同部分。如果把这些权重可视化，往往可以看到近似于词对齐 (word alignment) 的模式。

为了更具体地理解这一机制，下图展开了解码某一步时的完整计算过程：解码状态先与每个源状态打分，分数经 softmax 转换为权重，最后按权重对源状态求和得到上下文向量。

5.3 跨注意力与自注意力

像上面这样，读取需求来自一个序列（目标侧状态）、而被读取的内容来自另一个序列（源侧 memory）的注意力，被称为跨注意力 (cross-attention)，也称交叉注意力。这里的“跨”指的是表示的来源不同，而不是模态不同。与之相对，自注意力 (self-attention) 则是在同一个序列内部进行位置之间的信息聚合。

具体而言，如果目标侧有 $m$ 个查询位置、源侧有 $n$ 个位置，那么权重矩阵的形状为 $m\times n$，其中每一行表示一个目标位置对全部源位置的权重分配。在这种情况下，源端的补齐位置需要被屏蔽，而其余的源位置则全部可见，包括位于句子后半部分的内容。因此，跨注意力中的掩码与目标自注意力中的因果掩码，其含义是完全不同的。

在反向传播时，梯度从解码器的输出出发，经过状态传递或注意力聚合，一直传递到编码器的参数。例如，前面代码中的一次 loss.backward()，就同时为两部分的 Embedding 计算了梯度。因此，编码器学到的并不是一种通用的句子表示，而是对当前目标任务有用的表示。

而在推理方面，同一个源句只需要编码一次，得到的 memory 可以在所有生成步骤中复用。为此，可以把模型拆分为 encode(source) 与 decode(prefix, memory) 两个接口，从而直接表达这一数据流；相比之下，如果每一步都调用完整的 model(source, prefix)，虽然结果相同，却会重复执行源侧的计算。

7. 编码器—解码器与自编码器

最后，需要区分两个名称相近的概念。自编码器 (Autoencoder) 是另一类模型：它先把输入 $x$ 编码为中间表示，再将其重建为 $\hat x$，并以重建误差作为训练目标，常用于降维、去噪和表示学习。相比之下，翻译模型虽然同样包含编码器和解码器，但它的目标是另一个序列，因此属于序列转换任务。简而言之，“编码器—解码器”描述的是结构上的分工，而“自编码器”描述的是训练任务。

此外，编码过程也并不以“压缩”为必要条件。例如，Transformer 编码器的每一层都保持序列长度和模型维度不变，它所追求的是适合下游任务的表示，而不是更小或可逆的表示。

下图把这几种结构放在一起对比：

值得一提的是，这一套组件还可以拆开来单独使用：如果只保留编码器，并在其上接入分类头或逐位置预测头，就可以用于文本分类与序列标注（如 BERT）；如果只保留带因果掩码的解码器，则可以用于语言建模与文本续写（如 GPT）。而原始 Transformer 同时保留了两者，并通过跨注意力将它们连接起来：编码器处理完整的源序列，解码器处理目标前缀，而跨注意力则在每一层把源信息引入目标位置。
