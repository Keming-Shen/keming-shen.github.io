11 Transformer 的工程实现与应用

发表于2026-09-29|更新于2026-10-01|「CV」看得见的计算机视觉从神经网络到 Transformer
|浏览量:

实现 Transformer 时，除了网络层本身，还需要正确组织输入、掩码、训练目标与推理过程。事实上，PyTorch 已经提供了现成的编码器层与解码器层，真正容易出错的是它们之间的“胶水”部分，例如掩码的方向与形状、输入与标签的对齐、填充是否混入了损失，以及推理时的前缀管理。更麻烦的是，这类错误大多不会报错：模型照样能够训练，损失也照样会下降，只是学到的东西并不正确，例如在训练中偷看了答案，或者推理时的表现与训练时完全不一致。

1. 受控的序列转换任务

1.1 为什么使用合成数据

在验证实现的正确性时，真实的翻译数据存在两个缺点：一是训练成本高；二是当结果不理想时，很难判断究竟是实现有误、数据不足，还是模型太小。相比之下，合成数据集的规则已知、规模可控，可以先检查模型是否具备学习该规则的能力；若没有学会，还需区分实现错误、优化设置、模型容量和训练轮数等因素。这与软件测试中先用简单输入来验证逻辑的思路是相同的。

3.2 常见陷阱

除此之外，在构造掩码时还有以下几个常见的陷阱：

  • 掩码只作用于键。 填充位置作为查询时仍然会产生非零的输出，因为其表示会受到位置编码、偏置和归一化的影响。因此，这些位置的标签必须在损失中被排除。
  • 布尔语义不统一。 在底层函数 F.scaled_dot_product_attention 中，attn_mask=True 表示允许参与计算，这与 Transformer 层中的约定恰好相反。所以，在替换注意力实现时，需要同时转换掩码的语义，并检查其广播形状。
  • dropout 参数。 scaled_dot_product_attention 会直接根据 dropout_p 执行 dropout，而并不感知 model.eval() 的状态，因此在评估时必须显式地传入 dropout_p=0.0。

4.2 验证与检查点选择

在每个 epoch 结束之后，模型会在 eval() 模式下、关闭梯度记录的条件下计算验证损失；并且，每当验证损失创下新低时，就保存一份当前的参数。训练结束之后，载入验证损失最低的那组参数，再在测试集上进行评价。需要强调的是，测试集既不参与参数更新，也不参与检查点选择。

5. 自回归推理

训练完成之后，就可以进行推理。由于源序列在一次生成过程中保持不变，它的编码结果 memory 只需要计算一次。在此基础上，贪心解码从 <bos> 开始，每一步都选择最后一个位置上得分最高的 token，并将其追加到前缀中，直到生成 <eos> 或达到长度上限为止：

其中，torch.inference_mode() 比 no_grad() 更进一步，它禁用了版本计数等自动求导的簿记工作，因此推理开销更小。此外，12 是生成长度的上限，用于处理模型迟迟不产生 <eos> 的情况。需要注意的是，当模型位于 GPU 上时，source、prefix 以及掩码也都必须位于同一设备上。

在评价整句时，要求预测序列与参考序列完全一致，并且在正确的位置产生 <eos>。值得注意的是，即使逐 token 的准确率很高，整句仍然可能出错：一旦某一步选错，后续的条件就已经偏离了训练时的正确前缀（即第 05 章所讨论的曝光偏差）。

另外，这一实现虽然复用了源编码，但并没有缓存目标侧的键和值，因此每一步仍然会重新计算整个前缀。第 7.3 节将讨论如何消除这部分重复计算。

6.2 行为一致性测试

然而，准确率高并不能证明实现是正确的：一个偷看了答案的模型，在 teacher forcing 下同样能够达到 100% 的准确率。实现还应满足以下三条不依赖于训练效果的性质：

  1. 因果性：修改目标前缀中较晚位置的 token，较早位置的 logits 应当保持不变。如果因果掩码缺失或方向写反，这项测试就会失败。
  2. 源填充不变性：在源序列末尾追加填充之后，已有目标位置的 logits 应当在浮点误差范围内保持不变。这项测试同时检验了编码器与交叉注意力是否正确地屏蔽了源端的填充。
  3. 保存与载入：保存参数、模型配置和两个词表，重新构造模型之后，同一输入得到的 logits 应当与保存之前一致。

7. 计算复杂度与推理优化

7.1 计算量与中间存储

在完成了基本实现之后，接下来分析它的计算开销。设批量大小为 $B$、序列长度为 $L$、隐藏维度为 $D$，那么每一层的主要开销如下：

部分 计算量
Q/K/V 与输出投影 $O(BLD^2)$
注意力分数与加权求和 $O(BL^2D)$
FFN $O(BLDd_{\mathrm{ff}})$

由此可见，当序列较短时，投影与 FFN 在计算中占主导地位；而当 $L$ 超过 $D$ 的量级之后，注意力的二次项便会占据主导。

相比于计算量，存储上的压力往往更为突出。例如，如果显式存储每个头的注意力矩阵，就需要 $BhL^2$ 个元素：当 $B=8$、$h=8$、$L=1024$ 时，一共有 67,108,864 个元素，仅单个 float32 张量就要占用 256 MiB，这还不包括反向传播所需的其他激活、梯度以及优化器状态。对此，常用的缓解手段包括：

  • 按长度分桶：把长度相近的样本放入同一个批次，从而减少填充所造成的无效计算。
  • 混合精度：使用 float16 或 bfloat16 来存储和计算部分张量，从而降低显存与带宽的开销，但需要注意数值稳定性。
  • 激活重计算 (gradient checkpointing)：不保存部分中间激活，而是在反向传播时重新计算，以计算换取显存。

7.2 FlashAttention

在各种优化方法中，FlashAttention（Dao 等，2022）的出发点是：在现代 GPU 上，注意力的瓶颈往往不是浮点运算，而是需要在高带宽显存（HBM）与片上 SRAM 之间反复读写 $L\times L$ 的中间矩阵。为此，它把 Q、K、V 分块载入 SRAM，并用在线 softmax 逐块累积结果，从而不再需要在显存中存储完整的注意力矩阵；而在反向传播时，再按块重新计算。

值得强调的是，FlashAttention 计算的是精确的稠密注意力，只是浮点运算的顺序有所不同，因此可能带来极小的数值差异。它将额外的显存开销从 $O(L^2)$ 降低到了 $O(L)$，但运算量中仍然含有 $L^2$ 项。在 PyTorch 中，F.scaled_dot_product_attention 会在条件满足时自动选用这类高效内核。

7.3 KV 缓存

除了训练阶段的优化之外，推理阶段同样存在优化空间。在自回归生成中，第 $t$ 步只需要最后一个位置的输出。由于因果掩码的存在，已有位置的表示并不依赖于后续的 token；因此，在参数固定、dropout 关闭的情况下，追加新的 token 并不会改变各层中历史位置的键和值。基于这一性质，可以把每一层已经计算过的 K、V 缓存起来，每一步只为新位置计算 Q、K、V，再用新的查询去读取缓存。同理，交叉注意力中源端的 K、V 也可以在生成开始之前按层计算好，并在后续步骤中复用。

这样一来，每一步的计算就从“重新计算整个前缀”降低为“只计算一个位置”，其代价则是一个随生成长度增长的缓存。具体而言，设前缀长度为 $T$，那么对于标准的多头自注意力，每一层的缓存约为 $2BTD$ 个元素，其中系数 2 分别对应于 K 与 V。在长上下文场景中，KV 缓存常常会成为显存的主要占用者，并由此催生了一系列减少缓存的结构。例如，多查询注意力 (Multi-Query Attention, MQA)（Shazeer, 2019）让所有头共享一组 K、V；而分组查询注意力 (Grouped-Query Attention, GQA)（Ainslie 等, 2023）则让每一组头共享一组 K、V，从而在质量与缓存大小之间进行折中。

8. 结构变体与应用

8.1 三种结构

原始的编码器—解码器结构只是 Transformer 的一种用法。根据所保留的组件，可以将其分为以下三类：

结构 注意力模式 典型训练目标 代表模型 典型任务
仅编码器 双向自注意力 掩码语言建模 BERT 分类、序列标注、检索
仅解码器 因果自注意力 下一个 token 预测 GPT 系列 文本生成、对话、代码
编码器—解码器 双向 + 因果 + 交叉 条件生成 原始 Transformer、T5 翻译、摘要

其中，仅编码器 (encoder-only) 模型可以利用完整输入的双向上下文。对于分类任务，通常取一个特殊位置（如 BERT 中的 [CLS]）的表示，或者排除填充之后的平均表示，再接入分类头；而对于序列标注任务，则为每个有效位置输出一个标签。值得一提的是，BERT 通过随机遮盖部分 token 并对其进行预测来完成预训练，而网络结构与训练目标是两个相互独立的设计选择。

与之不同，仅解码器 (decoder-only) 模型去掉了编码器与交叉注意力，只保留带因果掩码的自注意力，并使用第 05 章介绍的下一个 token 预测进行训练。由于它把“输入”也视为前缀的一部分，一个模型便可以统一处理续写、问答、翻译等多种任务，这也是当前大语言模型的主流结构。

8.2 视觉 Transformer

更进一步地，Transformer 层处理的是向量序列，因此输入单位并不一定是文字。视觉 Transformer (Vision Transformer, ViT)（Dosovitskiy 等，2020）就把图像切分为不重叠的 patch，并把每个 patch 视为一个 token。例如，对于一张 $224\times224$ 的 RGB 图像，按照 $16\times16$ 进行切分，可以得到 $14\times14=196$ 个 patch；每个 patch 展开后包含 $16\times16\times3=768$ 个数，再经过线性投影变为 $D$ 维，最终组成一个形状为 [B,196,D] 的序列。

由于卷积核与步幅相同，并且没有填充，每个输出位置恰好对应于一个 patch 的线性投影，并且所有 patch 共享同一组投影参数。在此基础上，加入可学习的位置嵌入（否则模型无法感知空间布局，见第 08 章）以及一个分类 token 之后，长度为 197 的序列便可以送入标准的 Transformer 编码器，最后再由分类头把分类 token 的最终表示映射为类别分数。

综上所述，从文本到图像，改变的只是输入的切分方式与训练目标；而嵌入、注意力、残差连接、LayerNorm 与 FFN 这些基本模块则始终保持不变。这也正是 Transformer 能够成为多种模态通用架构的原因。
