00 Transformer 绪论

发表于2026-09-29|更新于2026-10-01|「CV」看得见的计算机视觉从神经网络到 Transformer
|浏览量:

文字、声音和图像承载着人们交流与认识世界所需的信息。自计算机问世以来，让计算机处理这些信息，并完成识别、理解与生成任务，是人工智能长期研究的课题。视频下方的自动字幕，需要把连续的声音转换为文字；机器翻译需要在不同语言之间保留语义；图像理解则需要把视觉内容组织成句子；人脸识别则需要将拍摄捕获的人脸照片和数据库里的信息去做比对。这些任务的输入形式不同，却有一个共同要求：要求机器能够接受单个词语、声音片段或图像的输入，还要利用它们之间的联系，结合整体信息作出判断，最终让机器也具备人类的一些思考与处理任务的能力。

2017年，来自 Google Brain 和 Google Research 团队的研究员 Ashish Vaswani 等人，在论文 Attention Is All You Need 中提出了 Transformer 这一划时代的范式，彻底颠覆了传统卷积和循环神经网络的范式，打通了超大规模并行训练的通路。尽管 Transformer 最初为了机器翻译任务而开发，但是此后，它逐渐成为大规模语言模型 (Large Language Model, LLM)、语音识别 (Automatic Speech Recognition, ASR)、图像分类与多模态模型的共同基础结构，开启生成式预训练模型 (Generative Pre-trained Transformer, GPT) 与统一架构时代的起点。时至今日， Transformer 依旧是文本、代码、图像、视频等各模态产品中的绝对主流。

1. 序列建模

1.1 序列数据与任务

序列 (Sequence)，泛指按顺序排列的一组元素。一段文本 (text) 可以看作由单个字符 (character)，或者词元 (token) 组成的序列，语音 (audio) 可以看作是单帧音频信号在时间上的序列，股票行情 (K线) 和传感器读数，也是在时间维度上的序列。按照输入与输出的形态划分，常见的序列任务可以分为以下四类：

任务形态 输入 → 输出 典型任务
序列分类 一个序列 → 一个类别 情感分析、垃圾邮件识别
序列标注 一个序列 → 等长的标签序列 命名实体识别、词性标注
序列到序列 一个序列 → 另一个变长序列 机器翻译、文本摘要、语音识别
语言建模 已有前缀序列 → 下一个元素的分布 文本续写、输入法联想

值得一提的是，原始 Transformer 针对的是序列到序列 (Sequence to Sequence) 任务（即前文提到的机器翻译）；其编码器部分可以单独用于分类与标注，解码器部分可以单独用于语言建模。

1.2 序列的属性与任务难点

序列的固有属性，给上述序列任务带来了一定的困难。具体而言，有以下三个序列任务都会面临的问题：

1. 序列长度可变。 以机器翻译任务为例：由于输入句子的长短不一，所以翻译前后的长度也不同。模型不能依赖固定的输入维度，并且由于不同语言的表达语序的不同，也不能假设输出与输入逐位置对应。

2. 序列的含义依赖上下文。 同一个词在不同语境中可以表达不同含义，例如：“苹果发布了新手机”和“把苹果削皮”中的“苹果”就表达了完全不一样的意思，前者代表美国的科技公司，而后者代表水果。因此，模型需要为同一个 token 在不同句子中产生不同的表示，这要求每个位置的 token 能够读取其他位置的上下文信息来理解这个 token 的实际含义。并且，随着上下文输入的信息越多，相关信息可能相距就越远。

3. 序列的顺序影响含义。 “狗咬人”与“人咬狗”，“我喜欢你”与“你喜欢我”，虽然包含相同的字，但是含义却不同。如果只统计序列中出现了哪些字符或者词语（即词袋表示），就不可避免会丢失序列中的信息。因此，对于序列级任务，模型的运算必须能够感知并利用元素之间的先后关系，要具备能够区分出不同意思的能力。

这些难点分别涉及变长序列的概率分解与自回归生成解决了序列长度的问题（第 02、05 章），跨位置读取信息的注意力机制聚焦于对序列上下文信息的理解（第 06–08 章），以及位置编码则帮助模型进一步理解不同顺序的 token 组合带来的多样化表意（第 08 章）。

2. 语言模型的演变

在 Transformer 出现之前，研究者已经围绕上述难点提出了多种建模方案。回顾这条技术演进路线，有助于理解 Transformer 的每一处设计分别是为了解决什么问题。

2.1 n-gram 语言模型

早期的统计语言模型 (Statistical Language Model) 采用马尔可夫假设 (Markov Assumption)：下一个词只依赖于它前面固定的 $n-1$ 个词。在这一假设下，条件概率可以直接通过语料中的计数来估计。以三元模型 (trigram) 为例，它用“前两个词之后出现某个词”的相对频率来估计 $p(w_t\mid w_{t-2},w_{t-1})$。

n-gram 模型简单且可解释，但存在两个根本性的限制。首先，窗口之外的信息被完全截断，模型无法利用 $n-1$ 个词以外的上下文。其次，随着 $n$ 增大，绝大多数词组合在语料中从未出现过，计数估计会变得非常稀疏，只能依靠各类平滑 (smoothing) 技巧来弥补。此外，n-gram 模型无法在相似的词之间共享统计信息，例如，“猫在睡觉”的计数并不会帮助模型估计“狗在睡觉”的概率。

2.2 循环神经网络

为了突破固定窗口的限制，循环神经网络 (Recurrent Neural Network, RNN) 用一个隐藏状态 (hidden state) 来概括已经读过的前缀，每读入一个元素就更新一次状态。由于状态的维度固定，而读入的序列可以任意长，RNN 能够自然地处理变长输入。与此同时，词嵌入 (word embedding) 使含义相近的词拥有相近的向量，统计信息因此得以在词之间共享，这也弥补了 n-gram 模型的另一项缺陷。

在此基础上，Sutskever 等人和 Cho 等人于 2014 年提出了基于 RNN 的编码器—解码器 (Encoder–Decoder) 结构：编码器读完整个源句后，把最后的隐藏状态作为整句的固定长度表示；解码器则以这一表示为条件，逐词生成译文。然而，这一结构存在以下两个问题：

  • 信息瓶颈：无论源句有多长，都必须被压缩成一个固定维度的向量，因此句子越长，信息损失越严重。
  • 顺序计算：第 $t$ 步的状态依赖于第 $t-1$ 步，所以同一层内的各个位置无法并行计算；并且，序列首尾两个位置之间的信息需要经过 $O(n)$ 次状态传递才能到达。

后来的长短期记忆网络 (Long Short-Term Memory, LSTM) 和门控循环单元 (Gated Recurrent Unit, GRU) 通过门控机制改善了长距离的梯度传播，但并没有改变上述两个结构性质。

以“今天／深圳／天气／很”为前缀，三元模型仅用“天气／很”预测下一词；RNN 则依次读取整个前缀，并通过隐藏状态传递信息。

2.3 注意力机制

针对信息瓶颈问题，Bahdanau 等人在 2014 年为编码器—解码器引入了注意力机制 (Attention Mechanism)。具体而言，编码器不再只输出最后一个状态，而是保留每个源位置的状态；解码器每生成一个词，都会根据当前状态计算对各个源位置的权重，再对源状态加权求和。这样一来，固定长度瓶颈被消除了，但编码器和解码器的内部仍然是循环结构，顺序计算的问题依旧存在。

Transformer 则在注意力机制的基础上更进一步：它完全去掉了循环结构，在编码器和解码器内部都使用自注意力 (Self-Attention) 来处理位置之间的依赖关系。不同层结构的计算性质可以从三个角度比较（其中 $n$ 为序列长度，$d$ 为表示维度，$k$ 为卷积核宽度）：

层类型 每层复杂度 顺序操作数 任意两位置间的最大路径长度
自注意力 $O(n^2d)$ $O(1)$ $O(1)$
循环层 $O(nd^2)$ $O(n)$ $O(n)$
卷积层 $O(knd^2)$ $O(1)$ $O(\log_k n)$

从表中可以看出，自注意力让任意两个位置在一层之内直接交互，并且同一层的所有位置可以通过矩阵乘法并行计算，这使它非常适合在 GPU 上进行大规模训练。但与此同时，它的计算量和中间存储会随序列长度的平方增长。这一代价也成为了后续长序列优化工作的主要出发点（第 11 章）。

3. Transformer 的整体结构

3.1 文本表示

首先，文本需要被转换为神经网络能够处理的数值形式。具体而言，分词器 (Tokenizer) 先将文本切分为 token，每个 token 在词表中对应一个整数编号；随后，嵌入表 (Embedding Table) 把编号映射为可学习的向量。由于自注意力本身对输入顺序不敏感（第 08 章），原始 Transformer 还需要为每个位置加上位置编码 (Positional Encoding)。经过这一步，输入序列被表示为一个形状为 $L\times d_{\mathrm{model}}$ 的矩阵，其中 $L$ 是序列长度。

3.2 编码器与解码器

在输入表示之上，原始 Transformer 由各 6 层的编码器与解码器堆叠而成：

  • 编码器层包含两个子层：多头自注意力 (Multi-Head Self-Attention) 与逐位置前馈网络 (Position-wise Feed-Forward Network, FFN)。编码器读取完整的源序列，输出每个源位置的上下文表示。
  • 解码器层包含三个子层：带因果掩码 (causal mask) 的自注意力、读取编码器输出的交叉注意力 (cross-attention)，以及 FFN。其中，因果掩码保证每个目标位置只能看到它之前的内容。

此外，每个子层都包裹在残差连接 (Residual Connection) 和层归一化 (Layer Normalization) 之中。这些组件的分工十分明确：注意力负责位置之间的信息汇聚，FFN 负责每个位置内部的非线性变换，残差连接和层归一化则保证多层堆叠之后模型仍能稳定训练。最终，解码器最后一层的输出经过一个线性层和 softmax，得到目标词表上的概率分布。

以“雨停了。”的英译为例，编码器计算中文源序列的表示，解码器根据源表示和已有英文前缀生成译文。

3.3 训练与推理的计算差异

需要注意的是，Transformer 在训练和推理两个阶段的计算方式并不相同。

在训练阶段，完整的正确译文是已知的。解码器以右移一位的目标序列作为输入，并配合因果掩码，就能在一次前向计算中同时得到所有位置的预测，再用交叉熵损失更新参数（第 04、05 章）。

而在推理阶段，下一个 token 依赖于模型此前生成的 token，因此只能从开始标记出发逐步生成。换言之，Transformer 在训练阶段消除了位置之间的顺序依赖，但自回归生成本身仍然是一个顺序过程。工程上的 KV 缓存等优化正是针对这一点而设计的（第 11 章）。

4. 知识依赖

综合前文，理解 Transformer 所需的基础知识来自三个方面：线性层与非线性激活构成了特征变换；条件概率与交叉熵定义了预测方式与训练目标；分词、嵌入与张量形状则规定了数据的表示方式。

在此基础上，序列建模又引入了自回归生成与编码器—解码器结构。其中，注意力、多头投影和位置编码决定了位置之间如何交互；残差连接、层归一化与前馈网络则决定了子层如何组织。这两组组件共同构成了完整的 Transformer，并最终落地为工程实现。

5. 符号约定

向量按行排列。$X\in\mathbb R^{L\times D}$ 表示一个包含 $L$ 个位置的序列，每个位置有 $D$ 个特征分量；批量张量的形状写作 [B,L,D]，其中 $B$ 为批量大小。线性层写作 $XW+b$，其中 $W$ 的形状为“输入维度 × 输出维度”。需要注意的是，PyTorch 的 nn.Linear 按相反的方向存储权重，实际执行的是 X @ weight.T + bias。

对数默认取自然对数。代码中的索引与位置编号从 0 开始，而数学公式中的下标则按各式的定义给出。此外，token 编号只在所属的词表内有效，不同词表中的同一个整数不必表示同一个 token。
