Linux服务器代理联网指南：Clash与Mihomo

发表于2026-09-20|更新于2026-10-05|「Linux」服务器操作指南
|浏览量:

Linux 服务器上的软件安装、代码拉取、模型下载和 API 调用，可能需要通过代理访问网络。本文使用兼容 Clash 配置生态的 Mihomo 核心，在用户目录中运行代理，再让需要联网的程序显式使用它。

使用前提：服务器具备基础网络连接，并且已有可用的上游代理配置。 上游可以是单位提供的代理、自行部署的节点或订阅服务，并不要求必须购买代理套餐。Mihomo 本身不提供节点，也不代替校园网认证；仅使用 DIRECT 时，请求仍从服务器原有网络直接发出。

所有 Linux 命令均在服务器的 Bash 终端执行。安装和运行使用普通用户权限，代理端口设为 7890，不启用 TUN、透明代理或系统路由修改。SSH、VS Code 与 tmux 的基础操作可参考 AI Coding指南。

不同程序对变量名的支持不同，示例同时设置大小写以兼容常见工具；其中 curl 对 HTTP 代理只接受小写 http_proxy。no_proxy 指定不经过代理的主机，可按需加入直接访问的服务域名。详细匹配规则因程序而异，见 curl 代理环境变量说明。

7. 常见问题

程序提示 Exec format error 或 Illegal instruction

前者通常表示下载的系统或 CPU 架构不匹配；后者可能是 CPU 不支持该构建的指令集。重新核对 uname -m 与发行包，AMD64 机器优先尝试 amd64-v1。文件已有执行权限却无法运行时，还需检查安装目录是否被挂载为 noexec，并使用管理员允许执行程序的位置。

配置检查失败

按错误行号检查 YAML 缩进、重复键和节点引用。完整配置与 provider 的节点列表结构不同，不能互换；从桌面环境复制的绝对路径也可能在服务器不存在。分享错误信息前移除节点凭证与订阅地址。

address already in use 或 Connection refused

前者通常表示端口已被其他进程占用，后者通常表示目标端口没有程序监听。可以检查：

已有自己的实例时直接复用；端口属于其他用户时，为自己的 mixed-port 选择其他空闲高位端口，并同步修改代理变量。不要终止不属于自己的进程。

配置正确，但请求一直超时

先查看日志确认代理已启动，再区分目标域名解析、节点连接、TLS 握手和网站响应分别在哪一步失败。为测试命令设置超时，可以避免终端无限等待；没有报错或没有输出，都不能作为联网成功的依据。

如果启动时下载规则或 GEO 数据失败，需要先准备配置引用的文件，或使用当前可直接访问的可信下载来源。订阅在 PC 上可用也不保证服务器能连接同一节点；不要通过关闭证书验证来掩盖 TLS 错误。

curl 可用，但 IDE 或某个扩展仍不能联网

检查该程序运行在 PC 还是服务器、何时启动、是否支持代理环境变量。给终端设置变量不会改变已经运行的 VS Code Server。VS Code 的本地与远端代理配置，以及 SSH 转发 PC 代理的另一种方式，见 AI Coding指南。

请求成功，但出口没有变化

检查 Mihomo 日志中的匹配结果、mode、分流规则和代理组选择。规则命中 DIRECT 时，请求仍可经过本地监听端口，但最终由服务器直接访问目标；经过 127.0.0.1:7890 不等于必然使用上游代理。

Linux服务器GPU监控指南：nvidia-smi与nvitop
