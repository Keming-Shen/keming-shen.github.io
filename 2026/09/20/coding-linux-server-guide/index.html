面向Linux服务器的Coding指南

发表于2026-09-20|更新于2026-09-27|「Linux」服务器操作指南
|浏览量:

Linux 服务器上的开发通常围绕一条工作流展开：通过 SSH 登录，在远端配置环境、编辑代码并运行任务，再通过日志和资源监控确认运行状态。个人电脑提供交互界面，服务器提供计算资源与存储，两者通过网络连接协作。

本文按连接、开发、AI 辅助、联网配置和任务管理的顺序整理常用操作。示例以 Windows 本机 + Linux 服务器 + Bash 为主；没有特别说明时，Linux 命令均使用普通账户执行。

各环节的完整流程与排错方法另整理为独立文章，可按当前任务查阅：

  • SSH 连接、密钥认证与文件传输：从首次登录到跳板机、SFTP 和连接排查。
  • VS Code 远程开发：远端组件、扩展、解释器、端口转发与下载配置。
  • Codex CLI 安装、认证与自动化：普通用户安装、项目权限、交互开发与脚本调用。
  • tmux、日志与断线恢复：长任务的启动、监控、恢复和结束。
  • Python 环境管理与依赖复现：venv、Conda、解释器定位和环境迁移。
  • GPU 监控与资源排查：nvidia-smi、nvitop、设备选择与常见瓶颈。
  • Clash 与 Mihomo 代理联网：已有代理配置的部署、验证与按需启停。

1 总览：在服务器上开发意味着什么

1.1 为什么使用 Linux 环境

许多科研代码、GPU 计算工具与集群作业系统主要围绕 Linux 提供部署和运行说明。统一到服务器的 Linux 环境，可以减少路径、Shell 脚本、编译工具链与依赖版本的差异，也便于让数据和计算任务留在同一台机器上。

这并不要求个人电脑也安装 Linux。Windows 上的终端、SSH 客户端和 IDE 已能完成大部分远程操作；只有在确实需要本地 Linux 工具时，才有必要额外配置 WSL 等环境。

需要区分三个位置：

  • 本机：Windows 电脑，运行命令提示符、MobaXterm、VS Code 界面和浏览器。
  • 服务器：Linux 主机，保存远端代码与数据，运行 Python、编译器、训练任务和命令行 AI 工具。
  • 外部服务：软件仓库、模型接口、数据下载站点等，由实际发起请求的机器访问。

因此，本机安装了 Python，不代表服务器已经安装；本机能访问某个网站，也不代表服务器能访问。127.0.0.1 和 localhost 始终指向当前发起连接的那台机器。

1.2 开始前需要的信息

连接服务器至少需要主机地址、SSH 端口、用户名，以及密码或已授权的 SSH 密钥。若服务器只允许校园网、VPN 或跳板机访问，还需要先满足相应的网络条件。

2.4 使用 MobaXterm

MobaXterm 将 SSH 会话、终端和 SFTP 文件面板放在同一个界面中，适合经常连接多台服务器或传输文件的场景。

  1. 新建 Session → SSH。
  2. 在 Remote host 填写服务器地址，勾选 Specify username 并填写用户名，按实际情况设置端口。
  3. 密码模式：连接后按提示输入服务器账户密码。
  4. 密钥模式：在 Advanced SSH settings → Use private key 选择本机私钥文件，例如 id_ed25519，不是 .pub 文件；有私钥口令时再输入口令。
  5. 保存会话，之后从会话列表打开连接。

密钥模式仍要求对应公钥已写入服务器的 authorized_keys。连接后，左侧 SFTP 面板可用于上传和下载文件；该面板中的路径属于服务器。界面选项见 MobaXterm 官方文档。

3 在 VS Code 中远程开发

3.1 Remote - SSH 的工作方式

在本机 VS Code 中安装 Microsoft 发布的 Remote - SSH 扩展（ms-vscode-remote.remote-ssh）。它通过 SSH 在远端用户目录部署 VS Code Server：编辑器界面留在本机，远端文件访问、终端以及需要在远端运行的扩展由服务器处理。

这意味着保存远程工作区中的文件时，修改的是服务器上的文件；远程窗口中打开的集成终端也默认在服务器执行命令。它不是自动维护两份代码的文件同步工具。架构与要求见 Remote - SSH 官方说明。

4 AI 辅助编程与自动化科研

任务描述应包含输入、输出和执行边界。例如，要求“读取训练入口和配置，补充小样本检查，运行已有测试，并列出修改内容”，比只要求“把项目跑起来”更便于验证。涉及完整数据处理或 GPU 训练时，应先确定数据范围和资源预算。

5 代理联网与 VS Code 下载配置

5.1 代理设置为什么要区分本机和服务器

代理的作用是让请求先到达代理服务，再由代理服务连接目标站点。配置能否生效，取决于两个条件：应用是否读取这项配置，以及该应用能否访问配置中的代理地址。

例如，本机代理监听 127.0.0.1:7890，这个地址对 Windows 上的应用有效；在 Linux 服务器上设置同一个地址，访问的却是服务器自己的 7890 端口，不会自动连接到个人电脑。

在服务器上独立运行代理核心、导入配置和检查联网状态的完整流程，见 Linux服务器代理联网指南：Clash与Mihomo。下面侧重终端、SSH 转发与 VS Code 之间的配置关系。

6 使用 tmux 保留远端任务

6.1 tmux 解决的是什么问题

直接在 SSH 终端里运行程序，连接断开时，Shell 退出或终端挂断可能导致程序结束。tmux 在服务器上维护独立的会话和伪终端，SSH 连接只是附着到这个会话的一个入口；断开入口后，会话内的进程仍可继续运行。

因此，应先在服务器启动 tmux，再在 tmux 内启动长任务。之后即使 PC 断网、休眠，或关闭终端，也可以重新 SSH 登录并接回同一会话。会话模型见 tmux 官方入门文档。

tmux 保留的是会话，不保证程序永不退出。服务器重启、进程被终止、内存耗尽、作业达到时限或程序自身报错，都可能结束任务；依赖网络的程序还需要相应网络连接。纯本地计算即使服务器暂时断网也可能继续，而依赖 PC 代理的 API 任务会随代理通道中断而失去连接。

6.3 常用组合键

以下按键均先按 Ctrl+B 并松开，再按后续键；%、" 等符号需要按键盘布局配合 Shift 输入。

  • d：离开当前会话，任务继续运行。
  • c：新建窗口；n / p：切换到下一个 / 上一个窗口。
  • 0～9：切换到对应编号的窗口；w：打开窗口列表。
  • %：左右分屏；"：上下分屏。
  • 方向键：切换窗格；z：放大当前窗格或恢复布局。
  • [：进入历史输出查看模式；默认按键配置下按 q 退出。
  • ?：查看组合键帮助。

在空闲 Shell 中执行 exit 会关闭该窗格；最后一个窗格退出后，会话也会结束。exit 与 detach 的作用不同。结束实验后再关闭不再需要的窗格和会话即可。

6.4 tmux 与作业调度系统

若服务器由 Slurm 等系统管理，计算资源应通过调度器申请，长时间训练通常通过批处理作业提交。tmux 适合保持交互操作，但不能替代资源申请，也不能延长作业时限；登录节点上的 tmux 不会自动获得 GPU 计算资源。

Slurm 已提交的批处理作业通常不依赖提交时的 SSH 会话。作业是否继续、何时结束，由调度器与作业本身决定。参见 Slurm 用户入门。
