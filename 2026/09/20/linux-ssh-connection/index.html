Linux服务器SSH连接指南：密码、密钥与文件传输

发表于2026-09-20|更新于2026-10-09|「Linux」服务器操作指南
|浏览量:

SSH 在本机与服务器之间建立加密通道，支持远程登录、执行命令、传输文件和端口转发。连接参数与认证配置确定后，命令行、MobaXterm 和 VS Code 可以围绕同一台服务器协同工作。

本文以 Windows 本机 + Linux 服务器 为例。标为“本机 CMD”的命令在 Windows 命令提示符执行；标为“服务器终端”的命令在登录后的 Linux Shell 执行。完整开发流程见 AI Coding指南。

1 连接前需要哪些信息

  • 服务器地址：例如 server.example.edu，也可以是管理员提供的 IP。
  • SSH 端口：默认通常为 22，以实际配置为准。
  • 用户名：本文示例为 alice。
  • 认证方式：账号密码，或已登记到该账号的公钥。
  • 网络入口：服务器是否要求 VPN、指定网络或跳板机。

密码与密钥认证都发生在 SSH 加密通道中。服务器是否接受密码、公钥或额外验证码，由其认证策略决定，客户端无法自行解除限制。

5 使用 MobaXterm 与可选的 ssh-agent

5.1 MobaXterm 会话

  1. 打开 Session → SSH，填写服务器地址、用户名与端口。
  2. 密码模式直接连接，按提示输入账号密码。
  3. 密钥模式在 Advanced SSH settings → Use private key 中选择 PC 上的私钥文件，不选择 .pub。
  4. 有私钥口令时，按提示解锁；服务器仍需事先登记对应公钥。
  5. 保存会话，后续从会话列表连接。

左侧 SFTP 面板显示服务器目录，可直接上传和下载文件。MobaXterm 的会话配置与 Windows OpenSSH 的 config 并不等同，修改一处后，应确认另一客户端仍使用正确参数。MobaXterm 官方文档

8 按连接阶段排查问题

8.1 超时、拒绝连接与认证失败

Connection timed out 通常发生在建立连接阶段，先核对地址、端口、VPN 和跳板机要求；Connection refused 通常说明目标端口没有接受连接的服务，或连接被明确拒绝。此时修改私钥通常无效。

Permission denied 表示已经进入认证阶段。检查用户名、服务器允许的认证方式、实际加载的私钥，以及对应公钥与权限。使用 agent 时若出现 Too many authentication failures，可通过正确的 IdentityFile 和 IdentitiesOnly yes 限定尝试身份。

8.2 主机指纹发生变化

出现 REMOTE HOST IDENTIFICATION HAS CHANGED 时，先停止连接，核对地址是否正确，并向管理员确认是否重装系统、更换主机或更新主机密钥。确认新指纹可信后，再删除本机中该主机的旧记录。

8.3 查看诊断日志

在本机 CMD 执行 ssh -v lab，可看到配置读取、连接建立和认证尝试。日志会显示主机地址、用户名、密钥路径与指纹，通常不打印私钥正文；共享日志时仍应移除内部地址和账号等信息，不要附上私钥文件。

命令行连接确认正常后，可继续配置 VS Code Remote-SSH 远程开发。服务器访问外部仓库与 API 的网络代理属于另一层配置，见 Linux服务器代理联网指南：Clash与Mihomo。
